## Clipvault 0.3.3 — обновление больше не падает с «timeout: global»

- **Исправлена ошибка обновления `timeout: global`.** Раньше на всё обновление (запрос к GitHub и скачивание ~17 МБ) был один общий лимит в 120 секунд — на медленном соединении он выходил раньше, чем кончалась загрузка. Теперь общего лимита нет: у каждого этапа свой (соединение 15 с, ответ 45 с, тело — до 20 минут).
- **Маршрут к GitHub.** Сначала запрос идёт напрямую, и только если не вышло — через прокси из переменных окружения (`HTTPS_PROXY`). Прокси, настроенный под другие программы, часто не пускает на GitHub и раньше съедал все 120 секунд.
- **Обрыв загрузки** посреди файла теперь повторяется до трёх раз, а не сразу показывает ошибку. Контрольная сумма проверяется по-прежнему.

## Файлы релиза

| Файл | Что это |
| --- | --- |
| `Clipvault-Setup.exe` | установщик: ставит в `%LOCALAPPDATA%\Programs\Clipvault`, права администратора не нужны |
| `Clipvault.exe` | переносная версия (тот же файл); её же скачивает автообновление |
| `clipvault-cli.exe` | консольная версия: `list`, `search`, `get`, `transform`, `purge` |
| `SHA256SUMS.txt` | контрольные суммы |

## Что важно знать

- **Обновление с 0.3.1 / 0.3.2 придётся сделать вручную один раз:** старый обновлятор тот самый, что падает по таймауту. Скачайте `Clipvault-Setup.exe` (или `Clipvault.exe` поверх старого, закрыв программу) — история, сниппеты и ключ останутся на месте. Дальше «Обновить» в окне работает уже новым кодом.
- **SmartScreen.** Исполняемые файлы **не подписаны**; сверяйте `SHA256SUMS.txt`.

## Ограничения

- Прямой запрос к GitHub и проверка версии проверены на этой машине; **полная загрузка нового релиза через обновлятор** (из-за того, что 0.3.3 — последняя версия) и сценарий «прямое соединение недоступно, работает только прокси» **не проверялись**.
