## Clipvault 0.2.0 — защита секретов, флаги менеджеров паролей, чёрный список

Версия учит Clipvault не записывать то, что записывать нельзя: пароли, ключи, сид-фразы, карты.

- **Фильтр секретов до записи на диск.** Распознаются: ключи и токены (`sk-…`, `ghp_`/`gho_`/`github_pat_…`, `AKIA…`/`ASIA…`, `xox…`, `AIza…`, `sk_live_…`, JWT), закрытые ключи (`-----BEGIN … PRIVATE KEY-----`), строки подключения (`postgres://user:пароль@хост`, `mongodb+srv://…`, `Server=…;Password=…`), сид-фразы BIP-39 (слова из словаря, число слов 12/15/18/21/24, проверка контрольной суммы), номера карт (13–19 цифр, Luhn и допустимое начало номера), строки, похожие на пароли (энтропия, набор символов, длина; чувствительность «выкл / низкая / средняя / высокая») и ваши регулярные выражения (по одному в строке в «Настройках»; не скомпилировавшиеся строки подсвечиваются).
- **Политика на срабатывание** (в «Настройках»): «не сохранять»; «держать только в памяти и стереть из буфера через N секунд» (по умолчанию 30; буфер стирается, только если в нём всё ещё этот секрет); «сохранить, но замаскировать» (на диск идёт `•••••••• [тип]`, оригинал не сохраняется). Запись «только в памяти» видна в списке скрытой, кнопка «Показать» раскрывает её, при выходе из программы она исчезает.
- **Флаги самих приложений.** Копии, у которых выставлены `ExcludeClipboardContentFromMonitorProcessing`, `Clipboard Viewer Ignore`, `CanIncludeInClipboardHistory = 0` или `CanUploadToCloudClipboard = 0`, не создают записи (отключается в «Настройках»).
- **Чёрный список процессов** по владельцу буфера (`GetClipboardOwner` → exe): по умолчанию KeePass, KeePassXC, Bitwarden, 1Password, Dashlane; список редактируется. Флаги и чёрный список проверяются **до** чтения содержимого буфера.
- **В журнале, отчётах о сбое и диагностике — только типы и счётчики** («распознан секрет: ApiKey, политика MemoryOnly»), никогда содержимое.

## Файлы релиза

| Файл | Что это |
| --- | --- |
| `Clipvault-Setup.exe` | установщик: ставит в `%LOCALAPPDATA%\Programs\Clipvault`, права администратора не нужны |
| `Clipvault.exe` | переносная версия (тот же файл); её же скачивает автообновление |
| `clipvault-cli.exe` | консольная версия: `list`, `search`, `get`, `purge` |
| `SHA256SUMS.txt` | контрольные суммы |

## Что важно знать

- **Обновление с 0.1.0:** кнопка «Обновить» в окне или `Clipvault.exe --update`; история и ключ остаются на месте.
- **SmartScreen.** Исполняемые файлы **не подписаны**: Windows может показать «неизвестный издатель». Сверяйте `SHA256SUMS.txt`.
- **Приватность.** Никакой синхронизации, облака и телеметрии; единственный сетевой запрос — проверка новой версии (отключается).
- Список слов BIP-39 (BSD-2-Clause) лежит в репозитории: `crates/core/src/bip39_en.txt`.

## Ограничения

- Проверено на реальной системе (Windows 11, `scripts/e2e.ps1`): политика «в памяти» (секрета нет ни в списке, ни в файлах данных, он стирается из буфера через заданное время, обычный текст не стирается), «не сохранять», «маскировать», свой шаблон, четыре формата-флага (и то, что флаг «можно» записи не мешает), чёрный список процессов. Таблицы положительных и ложных срабатываний (ключи, PEM, сид-фразы, Luhn, телефоны, ссылки, UUID, хеши, версии, идентификаторы) — модульные тесты.
- **Не проверено на реальной системе:** работа с настоящими менеджерами паролей (KeePass, Bitwarden, 1Password, Dashlane): мы проверяли сами форматы-флаги и имена процессов, но не эти программы; облачный буфер и история `Win+V` Windows; поведение при вставке из окна администратора через `--admin` с настоящим UAC.
- Фильтр — эвристика. Пароль, не похожий на пароль («лето2026»), пройдёт; случайная строка со смесью символов может быть принята за пароль (понизьте чувствительность). Сид-фраза с опечаткой (все слова из словаря, число слов верное, контрольная сумма не сходится) считается секретом.
- Стирание буфера не отменяет того, что другая программа успела прочитать его раньше. Секрет, оставленный «в памяти», хранится в памяти Clipvault до выхода из программы.
- Секреты внутри списков файлов и изображений не ищутся (только текст).
